## Decisions

- Decision: replace the fake chat panel with Activity instead of building local chat.
- Reason: the project already has a game log, and a nonfunctional chat affordance weakens product trust during review.
- Alternatives: implement a local-only chat message composer.
- Reversibility: a future local chat can be added as a separate panel without changing rules code.

- Decision: keep utility dialogs inside `App.tsx` for this slice.
- Reason: the current app is still a compact single-screen prototype and the dialogs share existing state directly.
- Alternatives: split utility dialogs into a separate component module now.
- Reversibility: extraction is straightforward if U020-U024 add automated UI smoke tests or more settings.
